> **갱신 2026-11-17** — v5 의 풀런 두 번 (`loso_L21`, `inlayer`) 의 결과를 반영했고, 첫 실험 (P0) 을 inlayer 방식으로 바꿨다. 바뀐 곳은 §1.2 에 모았다.

> 배선이 맞고, 정의가 그대로인 클래스는 v5 와 같고, 결함 8종이 모두 복사 기준선을 넘는다. IS (재현율 0.24) 와 OM 은 따로 읽어야 한다.

> DIVA 내보내기를 읽는 쪽 (P1) 은 아직 없다.
> v5 는 검증 fold 둘 (`loso_L21`, `inlayer`) 과 전수 학습이 끝났다 (§1.1).
> 근거 문서: [docs/DEFSEGAM_CLASS_UPDATE.md](../docs/DEFSEGAM_CLASS_UPDATE.md) — 아래에서 "안내서" 라 부른다.
> 클래스의 단일 출처는 DIVA 의 `backend/modules/Labeling/schema_pbf_2026_11.json` 이다.
>
> **v5 와의 관계.** 두 실험 모두 DSCNN 예측을 학습에 쓰지 않고 사람 GT 만으로 학습한다.
> - v5 = 클래스 체계는 v4 그대로 (11-class). **학습 방식만** 바꾼다: Stage 1 KD 폐지, decoder 를 무작위 초기값에서 단일 단계로,
>   길이는 step 기준, EMA 0.999, 검증 · 길이 결정을 사람 GT 로. 구현되어 있다.
> - v6 = v5 의 학습 방식 **위에** 아래를 더한다.
>
> v6 가 더하는 것:
> - **클래스 공간 교체**: v4 · v5 의 11-class → DIVA 레이블 체계 `pbf-2026.11` (정상 2 + 결함 8 = 10, id 0–9)
> - **학습 데이터에 DIVA 내보내기 추가**: DIVA 내보내기 (M160·M280) + Peregrine 공개 주석 (`DSCNN_Dataset`, 8 소스 125 레이어 — 새 체계로 재매핑)
> - **검증을 DIVA 레이블로**: 공정 단위로 나눈 val / test. v5 는 Peregrine 주석을 떼어 검증한다.
>   DIVA 데이터가 오기 전의 첫 실험 (P0) 만 v5 와 같은 inlayer 로 한다
> - **방향 규약 명시**: 모델 입력은 리코팅 축이 가로 (v4 API 의 90° 회전 규약 그대로)
> - **Copy-Paste 위치 규칙**, sampler 의 도메인 비중

**첫 실험은 P0 다 (§7.1).** Peregrine 주석만으로, v5 의 `inlayer` fold 와 같은 22 레이어를 검증으로 떼어 새 클래스 체계를 처음 돌려 본다
(2026-11-17 결정). DIVA 내보내기가 없어도 할 수 있고, 그 전에 정해야 하는 것은 §12 의 D3 하나다 (D1 은 DIVA 데이터를 캐시로 만들 때,
D4 는 2026-11-17 에 사진을 보고 레이어 단위로 판정해 데이터셋에 넣었고, 사람의 확인이 남았다 (§2.4). D9 는 v5 가 Peregrine 주석을 정답 데이터로 쓰면서 기본값이 정해졌다).
길이 · EMA 값은 v5 의 두 fold 에서 확인한 값이다 (§1.1). DIVA 데이터에 관한 수치 (게이트, 분할 비율) 는 아직 제안값이다.

**용어** (v5 계획서의 표와 같은 뜻이다. 이 문서에서 자주 쓰는 것만)

| 말 | 뜻 |
|---|---|
| step | 이미지 한 묶음 (16장 = GPU 4대 × 4장) 을 보고 가중치를 한 번 고치는 것. 학습 길이를 이 횟수로 센다 |
| EMA | 학습용 가중치와 따로 들고 가는 평균 사본. 검증 · 저장 · 배포에는 이 사본을 쓴다 (§5.3) |
| fold | 정답 데이터의 일부를 검증용으로 떼어 두고 나머지로 학습하는 한 번의 실행 |
| **inlayer** | 소스 (또는 공정) 마다 레이어 일부만 검증으로 떼는 fold. 같은 빌드의 다른 레이어가 학습에 남으므로 모든 클래스를 채점할 수 있지만 값이 낙관적이다 |
| loso (leave-one-source-out) | 소스 (장비 · 재료) 하나를 통째로 떼는 fold. 본 적 없는 장비에서의 성능을 잰다 |
| 결함 mIoU | 결함 클래스 IoU 의 평균. 그 실험에서 학습 화소와 검증 화소가 모두 있는 클래스만 넣는다 |
| 정밀도 / 재현율 | 정밀도 (precision) = 모델이 그 클래스라고 한 화소 가운데 맞은 비율. 재현율 (recall) = 정답이 그 클래스인 화소 가운데 모델이 찾아낸 비율. 재현율이 낮으면 "놓친다", 정밀도가 낮으면 "잘못 짚는다" |
| 기준선 | 새 모델과 같은 표본에서 채점해 나란히 놓는 비교 대상. 학습을 새로 하지 않는다 |

## 0. 전제 — "정답 데이터만" 의 범위

| 자원 | v4 에서의 쓰임 | v6 (v5 와 같은 원칙) |
|---|---|---|
| ORNL HDF5 `slices/segmentation_results` (DSCNN 예측 mask) | Stage 1 라벨, Stage 2 ckpt 선정 (Build 1 mIoU), Stage 1 Copy-Paste supplier, sampler 통계 | **학습 · 길이 결정 · ckpt 선정 어디에도 쓰지 않는다** (참고용 figure 에서만 읽는다, §6.5) |
| v1–v4 checkpoint | Stage 2 초기화 | 초기화에 쓰지 않는다 (DSCNN 예측으로 학습된 가중치). v5 ckpt 로도 초기화하지 않는다 (클래스 공간이 다르다) |
| Peregrine 공개 주석 — `ORNL_Data/DSCNN_Dataset/**/annotations/*.npy` | Stage 2 GT | 사용 (새 체계로 재매핑, §2.3) |
| DIVA 내보내기 zip — 사람이 `labeled` · `reviewed` 로 확정한 레이어 | 없음 | 사용 (주 학습 · 검증 데이터, §3.2) |
| DINOv2 backbone | frozen | frozen (자기지도 사전학습, DSCNN 과 무관) |

- `DSCNN_Dataset` 은 폴더 이름과 달리 DSCNN 의 출력이 아니라 DSCNN 을 학습시키는 데 쓴 **사람 주석**이다.
  v5 가 이 주석만으로 학습하므로 v6 도 이것을 정답 데이터에 넣는다 (D9). DIVA 레이블만 쓰는 변형은 §7 의 A1 이고,
  바뀌는 것은 설정 한 줄 (`USE_LEGACY = False`) 이다.
- DIVA 의 레이블링 초안은 v4 출력이지만, 내보내기에는 사람이 완료 · 검수한 레이어만 들어온다 (안내서 §6).
  초안에 끌려간 레이블이 섞일 위험은 §13 에 적었다.
- **GT 만으로 decoder 를 처음부터 학습하는 것은 v5 가 처음이다.** v1–v4 는 모두 Stage 1 에서 출발했고, v4 의 `stage2_best.pt` 는
  가중치의 약 86% 가 Stage 1 에서 넘어온 초기값이다 (근거는 [PLAN_v5.md](../v5/PLAN_v5.md) §0 과 부록 B).
  v5 의 첫 풀런에서 이 방식이 동작한다는 것과 길이 · EMA 값이 맞다는 것을 확인했다 (§1.1). v6 는 그 값을 그대로 쓴다 (§5.2–5.4).

### 1.1 v5 실험에서 확인한 것 (2026-11-17)

| v5 실행 | 상태 | v6 에서의 쓰임 |
|---|---|---|
| `loso_L21` — L21 (ConceptLaser M2, 20 레이어) 을 통째로 떼고 나머지 7 소스 105 레이어로 학습. 10,000 step | **완료** | 아래 1–9 |
| `inlayer` — 소스마다 레이어 5개 중 1개 (22 레이어) 를 떼고 103 레이어로 학습. 10,000 step | **완료** (2026-11-17 13:18, 119분) | 아래 10–16. P0 의 비교 대상이다 (§7.1) |
| `loso_MS` · `loso_I2` · `loso_GP` | 돌리지 않았다 | 길이를 여러 fold 의 평균으로 다시 확인할 때 필요. P0 는 기다리지 않는다 |
| 전수 학습 (`full`) — 125 레이어 전부, 검증 없음. 10,000 step | **완료** (2026-11-17 16:02, 114분) — `full/last.pt` | 기준선 B1 (§6.3) 에 쓴다 |

`loso_L21` 의 결과와 그것이 v6 에 뜻하는 것. 수치는 따로 적지 않으면 검증 20 레이어 · 마지막 step · EMA 사본의 값이다.
곡선에서 읽은 값 (2–4, 6) 은 1036² 에서, 나머지는 native 해상도에서 채점했다 (같은 모델의 결함 mIoU 가 0.179 대 0.178 로, 차이는 0.001 이다).

1. **사람 GT 만으로 학습된다.** loss 가 2.43 에서 0.04 로 내려갔고, 학습에서 한 번도 보지 못한 장비 (L21) 에서
   Powder IoU 0.937, Printed 0.823, 결함 mIoU 0.178 (RS · IS · Swelling · Debris · SE 5종) 이 나왔다.
   → Stage 1 없이 단일 단계로 가는 v6 의 전제를 유지한다.
2. **10,000 step 은 모자라지도 넘치지도 않았다.** EMA 곡선은 step 4,500 에 끝 값의 95% 에 닿고, 5,000 step 뒤로는 0.177–0.184 사이에서 평평하다
   (최고 0.184 @ 5,750, 끝 0.179 — 최고점의 97%). 그 사이에도 학습 loss 는 0.050 에서 0.04 안팎으로 내려갔다. 더 돌려도 본 적 없는 장비의 점수는 오르지 않는다.
   → `TOTAL_STEPS = 10,000` 을 그대로 쓴다 (§5.2). fold 하나의 결과이므로 DIVA val 로 다시 확인한다.
3. **EMA decay 0.999 는 이 길이에 맞다.** step 3,000 무렵까지는 EMA 사본이 학습용 가중치보다 낮게 나오고 (step 1,000 에서 0.073 대 0.125)
   그 뒤로는 같아진다 (끝에서 0.179 대 0.178). 검증마다의 흔들림은 EMA 쪽이 1/3 이다 (5,000 step 뒤의 표준편차 0.002 대 0.005).
   → 0.999 유지 (§5.3). 길이를 수천 step 아래로 줄인 실행에서는 EMA 값이 실제보다 낮게 나온다.
4. **가장 좋았던 지점 (best) 과 마지막 (last) 이 사실상 같다.** 차이 0.005 는 학습용 가중치 곡선이 검증마다 흔들리는 폭만 한 크기다.
   → v6 는 ckpt 를 고르지 않고 길이를 고른다. 배포 후보는 `last` 다 (§5.2, D13).
5. **틀리는 방식은 "놓침" 이다.** L21 의 결함 정답 화소 558만 개 가운데 74.5% 를 Powder 나 Printed 로 예측했다. 반대로 정상 화소를 결함으로 예측한 것은 0.3% 다.
   클래스별로도 정밀도는 높고 재현율이 낮다 (아래 표).
   → v6 의 지표에 정밀도 · 재현율과 놓친 비율을 함께 적는다 (§6.2). 평균 IoU 하나로는 이 양상이 보이지 않는다.
6. **클래스마다 가장 좋은 지점이 다르다.** IS 는 step 2,000 (0.264) 에서 가장 높았다가 끝에서 0.189 로 내려갔고, Debris 는 6,000 (0.308) → 0.277,
   SE 와 Swelling 은 끝까지 올랐다. 결함 mIoU 가 평평한 것은 오르는 클래스와 내리는 클래스가 상쇄된 결과다.
   → 클래스별 곡선을 함께 본다. IS 의 하락은 §2.4 (기존 IS 주석의 혼재) 와 같은 쪽을 가리킨다.
7. **v4 와 견주면 얻은 것과 잃은 것이 클래스별로 갈린다** (v4 는 이 20 레이어를 Stage 2 에서 학습했으므로 v4 에 유리한 비교다).
   아래 수치는 모두 "v5 대 v4" 순서의 IoU 다. v5 가 높은 것: IS 0.186 대 0.015, Debris 0.278 대 0.000, Swelling 0.224 대 0.167.
   v4 가 높은 것: SE 0.146 대 0.750, RS 0.056 대 0.154, Printed 0.823 대 0.873.
   v4 는 학습에 쓴 레이어인데도 IS 의 98%, Debris 의 거의 전부를 놓치고 (Debris 의 45% 를 Spatter 로 낸다), 정상 화소를 결함으로 짚은 양은 v5 의 2.9배다.
   → (a) 기준선 B0 (v4) 는 SE · RS 에서 강하고 IS · Debris 에서 0 에 가까울 것이다. 평균이 아니라 클래스별로 견준다 (§6.3).
   (b) DIVA 의 레이블링 초안은 v4 출력이므로 초안에 IS · Debris 가 거의 없을 것이다 (§13).
8. **loso 가 잰 것은 "다른 장비" 다.** 결함 mIoU 0.18 은 학습에 없던 장비에서의 값이고, 학습 loss 가 계속 내려가는 동안에도 오르지 않았다 — 길이나 EMA 로 풀리는 문제가 아니다.

그다음 사용자 요청으로 기존 IS 45 레이어를 하나씩 보고 IS / PS / 미레이블로 판정해 데이터셋에 넣었다 (§2.4 — IS 9, PS 33, 미레이블 3 레이어).
L21 · 17-4 · GP 의 16 레이어는 사용자가 준 규칙 — "경사면이 함께 나온 이미지는 PS, 나머지는 IS" — 을 따랐다.
원본이 경계선만 칠한 7 레이어 (17-4 5, GP 2) 는 사용자 지시대로 선이 가두는 영역 전체를 채웠다.
앞선 판의 기본값은 "검토 전에는 전부 미레이블" 이었다. 이제 P0 는 결함 8종을 모두 채점한다. 그에 따라 §2.3, §3.1, §3.2, §5.4–5.6, §7.1, §11–13, 부록의 수치와 문장을 고쳤다.
판정은 사람이 아니라 Claude 가 한 것이므로 확인이 필요하다 (D4).

마지막으로 v6 의 코드를 만들었다 (§10 — 로더 · 학습 · 채점 · 기준선 · 요약 · 검토 시트 · compose). 계획에 없던 것은 셋이다.
Copy-Paste 에서 자리를 뽑는 법을 정했다 (밑에 있어야 하는 클래스의 화소 위에 객체의 중심을 놓는다 — 고르게 뽑으면 SE · OM 이 거의 붙지 않는다, §5.5).
채점을 원본 해상도와 1036² 두 가지로 함께 낸다 (§6.2-8). compose 에 `baselines` 와 `convert` phase 를 더했다 (§10).
기준선 R2 · R3 를 실제로 채점해 §7.1 의 어림값을 실측값으로 바꿨다.

### 2.4 기존 IS 주석 — 레이어 단위로 IS / PS 로 나눴다

기존 주석의 Incomplete Spreading (Binder Jet 에서는 Powder Short Feed · Short Feed) 은 원인 (분말 부족) 으로 정의된 클래스라, 새 기준의 IS 와 PS 가 섞여 있다.
번호만 바꿔 2 로 옮기면 PS 여야 할 화소가 IS 로 학습된다. 그래서 45 레이어를 하나씩 보고 레이어 단위로 IS / PS 를 정했다.

**판정 (2026-11-17).** 사용자 요청으로 Claude 가 두 사진 (용융 직후 · 도포 직후) 의 전체와 경계 부근의 원본 해상도 확대를 보고 내렸다.
L21 · 17-4 · GP 의 16 레이어는 같은 날 사용자가 준 규칙대로 다시 판정했다 — **"경사면이 함께 나온 이미지는 PS, 나머지는 IS"**.
원본이 경계선만 칠한 17-4 · GP 의 7 레이어는 사용자 지시 — **"라인만 레이블링되어 있는데 영역을 전부 칠해 줘"** — 대로 선이 가두는 영역 전체를 채웠다 (아래 "영역 채움").
어느 이미지에 경사면이 보이는지는 Claude 가 본 것이고 **사람의 확인은 아직 없다.**
결과는 `v6/legacy_review.csv` (열: source, layer, decision, fill, judged, style, confidence, basis) 에 있고, 변환 스크립트가 기본으로 반영한다 (§3.1).

기준은 안내서 §3.2, [DEFECT_TAXONOMY.md](../docs/DEFECT_TAXONOMY.md) §4.4, 그리고 사용자의 예시 그림 (`paper/DefectSegAM_Ko/Figs/Defect_Examples_{IS_RH,PC}.png`) 이다.

- **PS**: 그림자가 지고 경사면이 보인다 — 분말이 무너져 내린 입체 형상. 용융 뒤에도 남아 두 사진에 다 보인다.
- **IS**: 평평하다. 덮이다 만 얕은 경계나 자국뿐이고 경사면이 없다.
- 판정은 이미지 (레이어) 단위다. 경사면이 한 곳이라도 보이면 그 레이어의 기존 IS 화소가 전부 PS 로 간다.

  같은 모서리가 드러난 `0000019` 와 다른 모서리의 `0000006` 에는 그런 띠가 없어 IS 로 뒀다. `0000161` 은 왼쪽 위 영역에만 띠가 보이지만 이미지 단위 규칙이라 왼쪽 아래 영역까지 PS 가 됐다.
- **PS 로 칠해지는 범위는 원본 주석 그대로다.** MS · H13 에서는 무너진 전면뿐 아니라 그 너머로 드러난 플레이트 바닥까지 PS 다. 안내서의 슬라이드 34 가 같은 영역을 PS 로 고쳐 부른 것과 같다.
- **영역 채움** (17-4 5 레이어, GP 2 레이어). 원본 주석은 덮이지 않은 (무너진) 영역이 아니라 그 경계선만 칠했다. 선이 이미지 가장자리와 함께 가두는 쪽을 찾아
  그 안의 Powder 화소를 그 레이어의 클래스로 바꿨다 — 17-4 는 PS 로 456 K px (레이어마다 이미지의 11–20%), GP 는 IS 로 899 K px (22%, 5%). 합쳐 native 1.36 M px 다.
  그 안의 Printed · SE · SP 와 미레이블 화소는 그대로 둔다 (GP 에서 드러난 파트는 원본이 이미 SE 로 칠했다). 선의 끝이 가장자리에 1–4 px 못 미치는 틈은 막고 채웠다
  (`legacy_map.enclosed_side` — 선과 막은 틈을 벽으로 삼아 나눈 덩어리 가운데 가장 큰 것, 곧 분말이 덮인 쪽을 뺀 나머지). 일곱 장 모두 그림으로 확인했다.
  **채운 화소는 ORNL 주석자가 Powder 로 둔 곳이다.** 경계선의 어느 쪽이 덮이지 않았는지는 사진으로 분명하지만, 영역의 바깥 경계 (이미지 가장자리까지) 는 원본에 없던 정보다.
- **BJ21 2 레이어의 IS 는 선 그대로다.** 막대 파트 가장자리를 따라 남은 짧은 선 자국이라 가두는 영역이 없다 (IS 화소의 0.6%).
- **PS 는 대부분 MS 한 소스다** (화소 수는 §2.3). L-PBF 소스의 PS 는 MS 외에 17-4 5 레이어와 L21 4 레이어다. IS 는 L21 5 레이어와 GP 2 레이어가 거의 전부다.
- 판정을 바꾸려면 `legacy_review.csv` 의 `decision` 을 고치고 변환을 다시 돌린다 (약 3분). 판정표를 쓰지 않으려면 `--no-is-review`.

v5 의 결과와의 관계 (§1.1-6, 15). v5 는 기존 IS 를 한 클래스로 배웠고, `inlayer` 에서 소스에 따라 갈렸다 — MS 0.990, H13 0.972 대 17-4 0.306, GP 0.304, L21 0.297, BJ21 0.187 (native).
높았던 MS · H13 이 이번에 PS 로 갔다. 낮았던 쪽은 원본이 선으로만 칠한 것 (17-4 · GP) 이거나 레이어에 따라 모양이 갈리는 것 (L21 · BJ21) 이다.

판정 전의 상태 (기존 IS 를 전부 미레이블로) 는 `--no-is-review` 로 만들 수 있다. 그때는 1036² 기준 12.5 M 화소 (전체의 9.3%) 가 손실에서 빠지고 IS · PS 의 학습 화소가 0 이다.

### 3.3 분할

검증이 무엇을 재는지는 떼어 두는 단위에 달려 있다. v6 는 쉬운 단계부터 올라간다.

| 단계 | 떼어 두는 단위 | 재는 것 | 값의 성격 | 쓰는 실험 |
|---|---|---|---|---|
| 1. inlayer | 같은 빌드 안의 레이어 일부 | 배선이 맞는가, 그 클래스가 배워지기는 하는가 | 낙관적 — 같은 빌드의 다른 레이어를 학습에서 봤다 | **P0**, P1 |
| 2. 공정 | DIVA 공정 (빌드 한 번) 통째 | 같은 장비의 새 공정에서의 성능 — **배포 조건** | 주 지표 | G1 파일럿, M0 · A1 · A3 · A4 |
| 3. 소스 (loso) | 장비 · 재료 통째 | 본 적 없는 장비에서의 성능 | 가장 엄격하다 | v5 `loso_L21` (결함 mIoU 0.18). v6 에서는 필요할 때만 (§7.1) |

배포 판단과 합격 기준 (§6.4) 은 2단계의 test 로만 한다. 1단계의 값은 "되는가 / 안 되는가" 를 가리는 데 쓰고 성능으로 옮겨 적지 않는다.

**1단계 — inlayer**

- **Peregrine 주석 (P0)**: v5 의 `inlayer` 규칙 그대로다 — 소스마다 레이어를 이름순으로 세어 5개마다 다섯째를 뺀다 (검증 22 레이어 / 학습 103 레이어).
  새 매핑의 화소표로 같은 규칙을 돌려도 v5 와 같은 22 레이어가 나온다 (2026-11-17 확인. 클래스 보정은 걸리지 않는다).
  기존 IS 의 판정을 넣은 뒤에도 이 22 레이어에 IS 3 레이어와 PS 6 레이어가 들어 있다.
  목록을 `v6/splits/legacy_inlayer_v1.json` 으로 고정한다 — 매핑 결정 (D3 · D4) 이 바뀌어도 검증 레이어가 흔들리지 않고, v5 `inlayer` 와 같은 표본으로 남는다.
- **DIVA 내보내기 (P1, 제안)**: 공정마다 레이블된 레이어를 번호순으로 놓고, 번호가 10 넘게 벌어지는 곳에서 끊어 덩어리로 묶은 뒤 덩어리 5개 중 1개를 검증으로 둔다.
  이웃한 층은 거의 같은 그림이라 레이어를 하나씩 떼면 값이 더 부풀기 때문이다. 덩어리가 5개 미만인 공정은 전부 학습에 둔다.
  수치 (10, 5) 는 첫 내보내기에서 레이블된 레이어가 어떻게 흩어져 있는지 보고 정한다.

**2단계 — 공정 단위**

- **단위는 공정** `(agency, mc_id, pp_id)`. 이웃한 레이어는 거의 같은 그림이므로 한 공정의 레이어는 전부 같은 분할에 둔다.
- **비율**: 공정 수 기준 train 70 / val 15 / test 15. 두 기종이 val · test 양쪽에 들어가고, 3개 이상 공정에 있는 결함 클래스가
  val · test 에 각각 한 번 이상 들어가도록 배정한다 (`split.py`, seed 고정).
- **고정**: `v6/splits/diva_split_v1.json` 을 git 으로 추적한다. 이후 내보내기에서 새로 생긴 공정은 train 으로만 간다.
  test 를 바꿔야 하면 `v2` 로 올리고 비교 대상 전부를 다시 채점한다.
- **공정이 2개 이하인 클래스** (예상: PS, RH): 그 공정을 레이어 구간으로 나눈다 — 앞 60% train, 30 레이어 간격, 나머지를 val · test 로 반씩.
  이 구간의 val · test 는 주 지표에 넣지 않고 그 클래스 전용 보조 지표로만 쓴다 (수치에 † 표시, 합격 기준에서 제외).
- **표본 편향 보정 (DIVA 에 요청)**: DIVA 는 v4 가 결함을 본 레이어 · 변화가 감지된 레이어 · 수동으로 고른 레이어만 레이블링한다
  (`pbf-sample-v1`). v4 가 놓친 결함은 덜 들어온다. val · test 공정마다 **무작위 레이어 10개**를 수동 추가로 레이블링해 달라고 요청하고,
  레이어 단위 지표 (§6.2-4) 는 이 표본에서만 계산한다.
- **Peregrine 주석**: M0 와 A2–A4 에서는 125 레이어 전부 train 이다 (v3/v4 와 같음). 22 레이어를 떼는 것은 P0 · P1 뿐이다.
- val · test 공정은 `reviewed` 비율이 높은 공정에서 먼저 고른다.

## 4. 방향 규약 — 리코팅 축은 가로

RS 와 RH 는 모양이 아니라 리코팅 방향과의 관계로 정의된다. 모델은 방향 메타데이터를 입력으로 받지 않으므로,
학습 · 추론의 모든 이미지를 **리코팅 축 = 이미지 가로 (x)** 로 맞춘다. 이 좌표계에서 RS 는 가로 줄, RH 는 세로 줄이다.

- **근거 1 — Peregrine 주석이 이미 이 방향이다** (2026-11-16 확인). v2022 6 소스의 `info.txt` 는 리코터 방향이 −x · +x · ±x 다.
  RS 성분 (200 px 이상; bbox 가로:세로가 2:1 이상이면 가로형, 1:2 이하면 세로형) 은 L21 · GP · I2 · MS · H13 에서
  가로형 535 K px, 세로형 0 이다. 메타데이터가 없는 BJ21 은 가로형 774 K / 세로형 94 K px 다. MS 의 RH 는 세로형 3.95 M px, 가로형 0 이다.
- **근거 2 — v4 API 규약과 같다.** DIVA 는 리코팅 축이 세로인 사진을 시계 90° 돌려 보낸다 (안내서 §5.2). DIVA 의 회전 코드를 바꿀 필요가 없다 (D1).
- **캐시 규칙**: DIVA 내보내기는 돌리지 않은 DIVA 방향이다. `recoat_axis == vertical` (기본) 이면 `visible/0` · `visible/1` · 라벨에
  `np.rot90(a, -1)` 을 건다 — DIVA 가 추론 때 하는 것과 같은 연산이다. `horizontal` 이면 그대로 둔다.
- **`recoat_axis` 가 내보내기에 없다** (D6). `index.csv` 에 열을 추가해 달라고 요청하고, 그 전에는 config 의 공정별 예외 표로 둔다.
- **서빙 계약도 같은 문장으로 쓴다**: "리코팅 축이 가로가 되도록 돌려 보낸다." 2026-11-09 판 DIVA 코드는 `recoat_axis` 와 무관하게
  항상 돌린다. `horizontal` 인 공정을 그렇게 보내면 RS 와 RH 가 뒤바뀐다 (v4 에서도 마찬가지다).
- **증강 · TTA**: flip LR / UD 와 180° 회전만 쓴다 (축 관계 보존). rot90 · transpose 는 쓰지 않는다 (v3/v4 와 같음).
- 좌우 (+x / −x) 는 통일하지 않는다. 소스마다 다르고 flip 증강이 덮는다.
- BJ21 의 세로형 RS 94 K px 는 레이어별로 확인한다 (§11-4 의 검토 시트에 포함).

## 5. 학습 설계

### 5.1 모델

`DefSegModel(backbone_name="dinov2_vitb14_reg", n_classes=10)` — v4 와 같은 구조 (frozen backbone ×2 → per-stage
`concat(f0, f1, f1−f0)` → DPT decoder), trainable 14.6 M. decoder 는 무작위 초기값에서 시작한다. `--init-from` 옵션은 학습 스크립트에 없다
(v5 의 `training/train.py` 를 복사해 출발한다 — 단일 단계 · step 기준 · EMA · rank 0 검증이 이미 들어 있다).
클래스 공간과 구조를 한꺼번에 바꾸면 원인을 가릴 수 없으므로 backbone · 입력 크기 (1036) 는 v4 · v5 그대로 둔다.

### 5.2 길이와 스케줄 — step 기준

내보내기가 늘 때마다 표본 수가 바뀌므로 길이를 epoch 이 아니라 optimizer step 으로 고정한다 (v5 와 같음).

- effective batch 16 (4 GPU × 4), AdamW, lr 2.83e-4, weight decay 1e-4, warmup 300 step → cosine, grad clip 1.0, AMP 끔 (v5 와 같음).
- **`TOTAL_STEPS = 10,000`.** v5 `loso_L21` 에서 이 길이는 모자라지도 넘치지도 않았고 (§1.1-2), `inlayer` 에서도 5,000 step 뒤로 평평했다 (§1.1-11). P0 는 v5 `inlayer` 와 조건을 맞추기 위해서도 같은 값을 쓴다.
  DIVA 레이블이 더해지면 데이터가 늘어나므로 DIVA val 곡선으로 다시 확인한다. 규칙은 v5 의 `summarize_cv` 와 같다 —
  최고점이 마지막 10% 구간에 있으면 늘리고, 끝 값이 최고점의 95% 아래로 내려갔으면 (과적합) `1.5 × 최고점 step` 으로 줄여 다시 돌리고, 그 밖에는 그대로 둔다.
- 250 step 마다 val 을 채점한다. 검증은 rank 0 혼자 val 전체를 한 번씩 돈다 (val 이 작아 `DistributedSampler` 의 패딩 중복이 지표를 흔든다).
  v5 에서 20 레이어 검증 1회 (학습용 가중치와 EMA 사본을 둘 다 채점) 가 6초였다.
- **ckpt 는 고르지 않고 길이를 고른다.** 배포 후보는 `last.pt` (정해진 길이의 마지막 EMA) 다. `best.pt` (val 결함 mIoU 최대) 도 저장해 test 로 함께 채점하지만 비교용이다.
  v5 `loso_L21` 에서 best (step 5,750, 0.184) 와 last (0.179) 의 차이 0.005 는 학습용 가중치 곡선이 검증마다 흔들리는 폭 (표준편차 0.005) 만 한 크기였고,
  클래스마다 가장 좋은 지점이 달라 (§1.1-6) 평균의 최고점을 고르는 것은 클래스 사이의 맞바꿈을 우연에 맡기는 일이 된다.
  `last` 는 learning rate 가 0 까지 내려간 뒤의 가중치이고, 고르는 단계가 없으므로 val 점수가 부풀지 않는다.
  (이 문서의 앞선 판은 `best` 를 후보로 했다 — D13.)

### 5.3 EMA

EMA (exponential moving average, 지수이동평균) 는 학습용 가중치와 따로 들고 가는 **평균 사본**이다.
매 step 뒤 `사본 ← decay × 사본 + (1 − decay) × 지금 가중치` 로 갱신하고, 검증 · 저장 · 배포에는 이 사본을 쓴다
(step 마다 흔들리는 값이 평균되어 결과가 안정된다). 사본은 학습을 시작할 때의 가중치에서 출발하며,
n step 뒤 그 출발값이 사본에 남아 있는 비율은 decay^n 이다. 1 / (1 − decay) 를 시상수라 한다.

| decay (시상수) | 1,550 step 뒤 남는 출발값 | 10,000 step 뒤 남는 출발값 |
|---|---|---|
| 0.9999 (10,000 step) — v4 | 86% | 37% |
| 0.999 (1,000 step) — v5 · v6 | 21% | 0.005% |

v4 Stage 2 는 0.9999 · 1,550 step 칸이고, 출발값은 Stage 1 결과였다 (§0).
v5 · v6 의 출발값은 무작위 값이므로 남는 만큼 그대로 손실이다.

- decay 0.999. 규칙: **시상수 ≤ 총 step 의 1/10**. `TOTAL_STEPS` 를 줄이면 decay 도 함께 낮춘다.
- 매 검증에서 EMA 가중치와 원 가중치를 둘 다 채점해 로그에 남긴다. EMA 가 뒤처지면 바로 보인다.
- v5 `loso_L21` 에서 확인한 것 (§1.1-3): step 3,000 무렵까지는 EMA 사본이 뒤처지고 그 뒤로는 학습용 가중치와 같아진다. 검증마다의 흔들림은 EMA 쪽이 1/3 이다.
  0.999 를 그대로 쓴다. `--quick` 처럼 짧은 실행의 EMA 점수는 실력이 아니라 뒤처짐을 보여 준다.

### 5.4 Sampler

v5 의 식 ([PLAN_v5.md](../v5/PLAN_v5.md) §5.4) 을 도메인 (Peregrine 주석 / DIVA 내보내기) 별로 적용하고, 도메인 사이의 비중을 따로 정한다.

```
share_diva = min(0.7, N_diva / (N_diva + N_legacy))             # 도메인 비중. Peregrine 쪽은 1 - share_diva
도메인 d 안에서:
  u_i = 1 / (그룹 수 × 그룹의 표본 수)                           # 그룹 균등. 그룹 = Peregrine 소스 / DIVA 공정
  c_i = (1 / 클래스 수) × Σ_c pix[i, c] / total_pix_d[c]         # 클래스 균등 (도메인 안에서, 화소가 0 인 클래스는 뺀다)
  q_i = 0.5 × u_i + 0.5 × c_i                                    # 합 = 1
  q_i ← min(q_i, 8 / N_d) 후 남은 몫을 비례 배분                  # 표본당 상한
p_i = share[d] × q_i
```

- 이 문서의 첫 판은 `u_i × c_i` (곱) 이었다. v5 를 구현하면서 곱이 Peregrine 주석 125 레이어 가운데 5개에 추출의 39% 를 몰아주고
  결함이 적은 소스를 거의 뽑지 않는다는 것을 확인해 (유효 표본 수 25 / 125) 혼합으로 바꿨다. 같은 데이터에서 혼합은 유효 표본 수 75 다.
- 그룹 균등은 v5 의 소스 균등을 DIVA 공정으로 넓힌 것이다. 레이어를 많이 레이블링한 공정 하나가 표집을 지배하지 않게 한다.
- 도메인 비중의 0.7 상한은 DIVA 에 드문 클래스를 Peregrine 주석으로 계속 보게 하려는 것이다.
- 혼합 비율 0.5 와 상한 8 은 v5 가 쓴 값 그대로다. v5 는 이 둘을 바꿔 가며 돌려 보지 않았으므로 실험으로 고른 값이 아니다 — 바꿀 근거가 생기기 전까지 둔다.
- 새 매핑으로 Peregrine 주석에서 계산하면 (2026-11-17, 기존 IS 의 판정 반영) 유효 표본 수는 125 레이어 전수에서 91, P0 의 103 레이어에서 74 다
  (v5 매핑에서는 75 · 60, 판정 전에는 85 · 68). Soot 가 Spatter 로 들어와 SP 를 가진 레이어가 11 → 67 개로 늘면서 추출이 더 고르게 퍼진다.
  P0 에서 소스별 몫은 7–8% (H13 · I1 · GP) – 20% (L21 · MS) 다.

### 5.5 증강과 Copy-Paste

- 증강은 v4 · v5 그대로: cyclic shift, flip LR / UD, 180° 회전, Gaussian noise · intensity shift (DSCNN 논문의 증강 방식일 뿐 DSCNN 출력과 무관), brightness jitter.
- Copy-Paste 는 v5 방식 (supplier 는 학습 분할의 GT) 에 위치 규칙을 더한다. 그 밖에는 v5 와 같게 두어 P0 를 v5 `inlayer` 와 견줄 수 있게 한다.
  - **위치 규칙**: v4 · v5 는 아무 자리에나 붙였다. 새 체계에서는 그러면 정의가 깨진다 (Printed 위에 붙인 Spatter 는 정의상 Over Melting 이다).

    | 붙이는 클래스 | 붙일 수 있는 자리 (target 라벨 기준) |
    |---|---|
    | SP (7), DB (9), IS (2), PS (3) | 객체 mask 의 90% 이상이 Powder 위 |
    | OM (8), SE (6) | 객체 mask 의 90% 이상이 Printed 위 |
    | RS (4), RH (5) | 제한 없음 |

    자리를 10번 뽑아도 조건을 못 채우면 그 객체는 붙이지 않는다.
    밑의 라벨은 그때까지 붙인 것이 반영된 라벨이다 (먼저 붙인 객체 위에 겹쳐 붙지 않는다).
  - **자리를 뽑는 법** (구현하면서 정했다, 2026-11-17): 제한이 있는 클래스는 target 에서 밑에 있어야 하는 클래스의 화소 하나를 고르고,
    객체의 무게중심을 거기에 놓은 뒤 90% 조건을 검사한다 (`CP_ANCHOR_ON_REQUIRED`). v5 처럼 이미지 전체에서 고르게 뽑으면 Printed 가 화소의 1할쯤이라 SE · OM 이 거의 붙지 않는다.
    P0 의 학습 103 레이어에서 1,500번 붙여 센 값 — 고른 객체 가운데 실제로 붙은 비율이 고르게 뽑을 때 SE 32% · OM 26% · DB 98%, 중심을 놓을 때 SE 79% · OM 61% · DB 99% 다
    (RH 는 제한이 없어 100%. v5 는 규칙이 없어 전부 붙였다). SE · OM 은 v5 보다 덜 붙는다는 뜻이므로, 이 둘이 v5 보다 낮게 나오면 `--no-copy-paste` 실행과 함께 본다.
    P0 에서 객체를 대는 레이어는 RH 21 · SE 59 · OM 13 · DB 28 개다.
  - **대상 클래스**: v5 가 붙이던 구성을 새 id 로 옮긴다 — RH (5) · SE (6) · OM (8) · DB (9). RS · SP · IS · PS 는 넣지 않는다.
    IS · PS 는 Peregrine 주석에서 화소의 95% · 99.7% 가 bbox 상한을 넘는 큰 영역이라 붙일 수 없다 (2026-11-17 계산). DIVA 레이블의 IS · PS 가 작은 덩어리로 들어오면 그때 다시 본다.
    새 매핑에서 RS 화소의 61%, SP 의 67% 는 bbox 상한 0.3 을 넘는 큰 성분 (판을 가로지르는 줄, 넓게 퍼진 그을음) 이라 어차피 붙일 수 없다 (2026-11-17 계산).
    RS 는 나머지 38% (성분 309개) 가 붙일 수 있는 크기다. v5 `inlayer` 와 P0 에서 RS 가 계속 낮으면 RS 를 대상에 넣는 것이 다음 후보다.
  - **도메인을 넘지 않는다**: Peregrine 객체와 DIVA 객체를 서로의 레이어에 붙이지 않는다 (밝기 · 해상도 차이가 크다). DIVA 객체는 같은 기종의 DIVA 레이어에만 붙인다.
    Peregrine 안에서는 v5 처럼 소스를 가리지 않는다 (앞선 판은 같은 소스로 제한했다. v5 와 조건을 맞추기 위해 풀었고, 제한할지는 A3 의 결과를 보고 정한다).
- 나머지 상수 (`CP_PROB` 0.5, 객체 최대 3개, feather σ 5, bbox 상한 0.3, 최소 30 px) 는 v4 · v5 값이다.

### 5.6 손실

`cross_entropy` + sqrt-inv class weight (clip 10), `ignore_index = -1` — v4 Stage 2 와 같다. hard-bootstrap 은 의사 라벨용이었으므로 뺀다.
학습 화소가 0 인 클래스는 정답으로 한 번도 나오지 않으므로 모델이 내지 않게 된다. 그런 클래스는 ckpt 의 `class_train_px` 에 0 으로 남겨 서빙 쪽이 알 수 있게 한다.
새 매핑의 Peregrine 주석 전수에서 class weight 는 Powder 0.58, Printed 2.90, PS 3.03, SP 6.10, RH 9.59, IS · RS · SE · OM · DB 10 (상한) 이다
(2026-11-17, 기존 IS 의 판정 반영. 판정 전에는 IS · PS 의 학습 화소가 0 이었다). PS 는 화소가 많아 화소당 가중치가 Printed 수준으로 낮다.

### 5.7 해상도와 라벨 축소

- 이미지는 BILINEAR, 라벨은 NEAREST 로 1036² 에 맞춘다 (v4 와 같음). 2026-11-16 에 Peregrine 주석 (축소 배율 0.74–4.7배) 으로 확인한 결과
  NEAREST 축소는 클래스별 면적비를 0.97–1.03 으로 보존하고 (성분이 1개뿐인 GP 의 RS 제외), 통째로 사라지는 것은 출력 한 화소보다 작거나 가는 성분이다.
  "블록 안 결함 비율이 25% 이상이면 결함" 방식은 면적을 최대 43% 부풀려서 채택하지 않는다.
- DIVA 전처리본의 크기는 공정마다 다르다 (안내서의 예는 1762×1812 로 배율 약 1.7배. DIVA 코드 주석에는 M280 원본 18 MP 가 나온다).
  `build_cache` 가 공정별 배율과 클래스별 면적비 · 성분 생존율을 로그에 남겨, 얇은 결함 (RS, SP) 이 얼마나 사라지는지 드러낸다.
- **평가는 native 해상도**에서 한다 (서빙과 같은 경로: logits 를 원본 크기로 bilinear upsample → argmax).

## 6. 평가

### 6.1 ckpt 선정

고르지 않는다. 정해진 길이의 마지막 EMA 사본 (`last.pt`) 이 후보다 (§5.2).
val 의 결함 mIoU (id 2–9 중 val support 가 있는 클래스의 평균, EMA 가중치, 1036² 에서 채점) 는 길이를 확인하고 학습을 지켜보는 데 쓴다.

### 6.2 지표 — DIVA test, native 해상도, TTA · 후처리 없이

1. 클래스별 IoU · precision · recall, mIoU (support > 0 인 클래스), **결함 mIoU** (id 2–9).
2. 기종별 (M160 / M280) · 공정별 같은 표. 원본 크기가 다른 공정을 합친 IoU 는 화소가 많은 공정의 값이 된다 —
   v5 `inlayer` 의 RS 는 같은 모델인데 합친 값이 1036² 에서 0.424, native 에서 0.261 이었다 (§1.1-15).
3. 혼동 쌍 4개 (IS↔PS, RS↔RH, SE↔DB, SP↔OM) 의 쌍 안 혼동률.
4. 레이어 단위: 결함 화소 비율 ≥ 0.003 (`pbf-sample-v1` 의 `min_frac`) 으로 "결함 레이어" 를 판정했을 때의 precision · recall — §3.3 의 무작위 표본에서.
5. 보조: TTA (flip LR × UD × 180°, 8-way) 와 후처리 (§8) 를 켰을 때의 변화.
6. 놓침과 잘못 짚음: 결함 정답 화소 가운데 Powder · Printed 로 예측한 비율, 정상 화소 가운데 결함으로 예측한 비율.
   v5 는 본 적 없는 장비 (`loso_L21`) 에서 앞의 값이 74.5%, 뒤의 값이 0.3% 였고, 같은 빌드를 학습한 `inlayer` 에서는 9.4% 와 2.6% 였다 (§1.1-5, 12).
   IoU 가 낮은 까닭이 어느 쪽인지 이 둘로 가린다.
7. 선으로 칠하는 클래스 (RH · RS) 는 IoU 와 함께 재현율을 읽는다. 주석이 가는 선이고 예측이 영역이면 맞게 찾아도 IoU 가 낮다
   (v5 `inlayer` 의 RH 는 재현율 0.89 에 IoU 0.36 — §1.1-13).
8. 구현 (`inference/evaluate.py`, `baselines.py`): 추론 한 번으로 원본 해상도와 1036² 의 표를 함께 낸다 (`eval_native_last`, `eval_resized_last`).
   주 지표는 원본 해상도다. 1036² 는 학습 곡선 · 복사 기준선과 같은 해상도라 그것들과 견줄 때만 쓴다. 3 · 6 번과 IS ∪ PS 를 합쳐 본 IoU, 소스별 표가 `metrics.json` 에 들어간다.

### 6.3 기준선 — B0 (지금 서빙 중인 v4) 와 B1 (v5)

둘 다 새 학습이 아니다. 11-class 예측을 `V4_TO_NEW` 로 옮겨 같은 test 에서 채점한다 (v5 는 v4 와 클래스 번호가 같아 같은 표를 쓴다).

- **B0 — v4** (`stage2_v4_11cls.pt`): 전환 기준선. DIVA 가 지금 쓰는 모델이다.
- **B1 — v5** (`…_11cls_v5/full/last.pt`): 같은 11-class 를 사람 GT 만으로 학습한 모델. B0 와 B1 의 차이는 DSCNN 예측으로 학습한 것과
  GT 만으로 학습한 것의 차이이고, B1 과 M0 의 차이는 클래스 체계 교체 + DIVA 레이블의 효과다.
  v4 와 v5 둘 다 본 적 없는 사람 GT 로 두 모델을 견주는 것은 이 채점이 처음이다 ([PLAN_v5.md](../v5/PLAN_v5.md) §6.3).
  v5 의 전수 학습은 2026-11-17 에 끝났다 (`…_11cls_v5/full/last.pt`). DIVA test 가 생기면 `baselines old` 로 채점한다.
- **v4 의 성향** (v5 의 참고 채점에서, §1.1-7, 16): L21 에서는 SE · RS 가 강하고 IS · Debris 는 거의 내지 않는다.
  L21 밖에서는 소스에 따라 크게 갈린다 — Stage 2 에서 학습한 소스인데도 Printed IoU 가 17-4 0.96, I1 · I2 0.55–0.65, MS 0.10 이다.
  M160 · M280 에서 B0 가 어느 쪽일지는 채점해 봐야 안다. 결함 mIoU 의 평균만이 아니라 클래스별 · 공정별로 견준다.

Swelling · Under Melting 예측은 DIVA 가 지금 하는 대로 미레이블로 두고 (그 화소는 놓친 것으로 센다), Swelling → SE 로 옮긴 변형도 함께 적는다.
두 기준선 모두 PS 를 낼 수 없다. DIVA 레이블은 v4 초안에서 출발하므로 이 비교는 v4 쪽에 유리하게 치우친다.

### 6.4 합격 기준 (제안)

- DIVA test 결함 mIoU: M0 의 3 seed 평균 (seed 마다 `last.pt`) 이 B0 보다 높고, 차이가 seed 표준편차의 2배 이상.
- Powder · Printed IoU 가 B0 보다 0.01 넘게 낮지 않다.

B0 가 그 장비에서 무너져 있으면 (Printed IoU 부터 낮으면) 위 기준은 저절로 채워져 판정이 되지 못한다 (§1.1-16).
G1 에서 B0 를 처음 채점할 때 이것부터 보고, 그렇다면 기준을 다시 정한다.

못 넘으면 배포하지 않고 B1 과 A1–A4 로 원인 (학습 방식 / 데이터 양 / Peregrine 주석 / Copy-Paste) 을 가린다.

   (먼저 `--no-copy-paste` 로 한 번 더 돌려 위치 규칙의 영향인지 가린다). 매핑이 바뀌면 sampler 의 추출 분포와 class weight 도 따라 바뀌므로
   (예: GP 의 몫 13% → 8%, SP 의 weight 10 → 5.7) 이 클래스들의 값도 조금은 움직인다.
   v5 `inlayer` 에서 마지막 2,000 step 동안 이 클래스들의 IoU 가 검증마다 흔들린 폭은 표준편차 0.002–0.006 이었다 (학습용 가중치 기준. 한 실행 안의 흔들림이고 seed 사이의 차이는 아니다).
3. **새 정의로 배워지는가.** 결함 8종의 IoU 가 모두 R1 보다 높다. R1 아래인 클래스는 가장 쉬운 조건에서도 배우지 못한 것이다 (§1.1 의 읽는 법과 같다).
   v5 는 같은 22 레이어에서 RS · RH · DB · SE 가 모두 복사 기준선을 크게 넘었다 (§1.1-10). P0 에서 이 넷이 R1 아래면 클래스가 어려운 것이 아니라 배선을 의심한다.
   P0 가 새로 알려 주는 것은 SP (Soot 가 합쳐진 정의, R1 0.418), OM, 그리고 IS 와 PS 가 갈라지는지다.
   PS 는 R1 이 0.81 이다 — 무너진 자리가 레이어가 바뀌어도 그대로라 베끼기만 해도 맞는다. PS 가 이 값을 넘지 못하면 모양이 아니라 자리를 외운 것으로 읽는다.
   IS 는 R1 이 0.15 로 낮다 (L21 의 미도포 영역은 레이어마다 자리가 다르고, GP 의 두 장만 자리가 겹친다). 외워서는 잘 안 되는 클래스이므로 IS 의 IoU 가 P0 에서 정보가 가장 많은 값이다.
   RH 는 주석이 가는 선이라 맞게 찾아도 IoU 가 0.36 근처에 머문다. 재현율 (v5 0.89) 과 예측 그림으로 읽는다 (§1.1-13).
4. **혼동 쌍.** IS↔PS, RS↔RH, SE↔DB, SP↔OM 의 쌍 안 혼동률과 정밀도 · 재현율, 놓친 비율 (§6.2-6) 을 적는다. 기준은 없다 — 새 정의에서의 첫 측정이다.
   v5 `inlayer` 는 놓친 비율 9.4%, 잘못 짚은 비율 2.6% (RH 를 빼면 0.4%) 였다. 소스별 표를 함께 낸다 — 합친 값은 채점 해상도에 따라 달라진다 (§1.1-15).
5. **곡선.** 결함 mIoU 와 클래스별 IoU 가 어디서 평평해지는지 v5 `inlayer` 의 곡선과 나란히 본다. 길이를 늘리는 근거로는 쓰지 않는다 (§1.1).

**넓히기 — 필요할 때만**

- **inlayer 5-fold** (4회 추가, 약 8시간): 뺄 자리를 바꿔 (5개마다 첫째 … 넷째) 네 번 더 돌리면 125 레이어 전부가 한 번씩 채점된다.

- **loso 1-fold** (1회, 약 2시간): L21 을 빼고 같은 조건으로. v5 `loso_L21` 과 나란히 놓아 새 매핑이 "다른 장비" 조건에서 어떤지 본다 (채점 결함 RS · SE · SP · DB).
- **판정 없이** (1회): `--no-is-review` 로 만든 데이터셋 (IS · PS 없음, 결함 6종) 으로 한 번 돌리면 IS · PS 를 넣은 것이 나머지 6종에 준 영향을 볼 수 있다.
- **판정을 고친 뒤 다시** (1회): 사람이 `legacy_review.csv` 를 고치면 (D4) 다시 변환해 한 번 더 돌린다.

### 7.2 P1 — DIVA 의 첫 내보내기가 오면 (제안)

공정 단위로 떼려면 공정이 여럿 있어야 한다 (G1 = 4개). 그 전에도 첫 내보내기에 레이블된 레이어가 30개쯤 있으면 inlayer 방식으로 DIVA 레이블을 넣은 실행을 한 번 할 수 있다.

- 학습: P0 의 103 레이어 + DIVA 의 학습 몫. 검증: P0 의 22 레이어 + DIVA 의 검증 몫 (§3.3 의 덩어리 분할). 도메인 sampler (§5.4) 와 회전 (§4) 이 여기서 처음 쓰인다.
- 보는 것: (a) DIVA 로더 · 회전 · `swap_sd` 점검 · 도메인 sampler 의 배선, (b) Peregrine 22 레이어의 점수가 P0 보다 내려가지 않는가 — DIVA 레이블을 섞어도 기존 클래스가 유지되는가,
  (c) IS · PS 처럼 DIVA 에만 있는 클래스가 배워지는가 (같은 공정 안에서 본 것이므로 낙관적이다).
- 이 실행의 DIVA 쪽 점수는 성능으로 옮겨 적지 않는다. 공정이 4개 모이면 G1 의 GroupKFold 로 넘어간다.

## 9. 서빙 인계 (`DefSegAM_API` repo — 이 계획의 범위 밖, 계약만 적는다)

- ckpt 의 `config` 에 `schema`, `class_keys`, `class_names`, `orientation`, `class_train_px`, 분할 판, 내보내기 manifest 를 넣어 API 가 이름을 코드에 적어 두지 않고 ckpt 에서 읽게 한다.

## 13. 위험 요소

- **GT 전용 학습은 되지만, 본 적 없는 장비에서는 결함을 대부분 놓친다** (§1.1). v5 `loso_L21` 의 결함 mIoU 는 0.18 이고 결함 정답 화소의 74.5% 를 정상으로 예측했다.
  v6 의 성능은 DIVA 장비의 레이블이 얼마나 들어오느냐에 달려 있다. DIVA 레이블이 적은 동안의 모델은 M160 · M280 에서도 같은 양상 (놓침) 을 보일 것으로 본다.
  같은 빌드를 학습한 v5 `inlayer` 에서는 놓친 비율이 9.4% 로 내려갔다 (§1.1-12). 그 사이 (같은 장비의 다른 공정) 가 어디쯤인지는 아직 잰 적이 없다.
- **inlayer 의 값은 낙관적이다** (§7.1). P0 · P1 의 점수를 성능으로 옮겨 적지 않는다. 복사 기준선과 함께 읽는다.
  v5 는 같은 모델 구성으로 inlayer 에서 결함 mIoU 0.45, 다른 장비에서 0.18 이었다 — 두 값의 차이가 이 낙관의 크기다.
- **검증 화소가 적은 클래스.** P0 에서 OM 은 5 K px (사실상 한 레이어), DB 는 27 K, RS 는 45 K 다. IS 는 379 K 지만 두 레이어 (GP · L21) 뿐이다. 한 fold 의 클래스별 값은 한두 레이어에 좌우된다 (§7.1 의 5-fold 로 넓힐 수 있다).
- **Peregrine 주석의 Spatter 는 사실상 Soot 다** (§2.3, D10). SP 화소의 89% 가 Soot 이고 60% 가 17-4 한 소스에서 온다. 넓게 퍼진 영역으로 칠해져 있어,
  DIVA 가 Spatter 를 "작은 점 여럿" 으로 칠한다면 두 도메인의 SP 가 서로 다른 모양이 된다. 첫 내보내기에서 SP 레이블의 모양부터 확인한다.
- **DIVA 레이블 수량을 모른다.** 게이트 (§3.4) 로 관리하고 A4 로 더 모을 가치를 판단한다. PS · RH 는 공정이 1개뿐일 수 있다.
- **v4 초안의 영향.** 레이블이 v4 출력에서 출발하므로 v4 의 버릇이 레이블에 남을 수 있고, 레이블링 대상 레이어도 v4 가 고른다.
  v4 는 학습에 쓴 L21 레이어에서도 IS 의 98%, Debris 의 거의 전부를 놓쳤다 (§1.1-7). 초안에 이 두 클래스가 거의 없을 것이므로 사람이 처음부터 칠해야 하고,
  이 두 결함만 있는 레이어는 "모델이 결함을 본 층" 기준으로는 레이블링 대상에 잘 들어오지 않는다. §3.3 의 무작위 표본과 `reviewed` 우선으로 줄인다.
  L21 밖에서는 v4 가 소스에 따라 Printed 부터 틀린다 (학습에 쓴 MS 에서 Printed IoU 0.10, §1.1-16). M160 · M280 의 초안이 어느 쪽인지 DIVA 팀에 먼저 확인한다 —
  초안이 무너지는 장비라면 사람이 처음부터 칠하는 것이라 레이블이 모이는 속도 (§3.4 의 게이트) 가 달라지고, B0 는 기준선 구실을 못 한다 (§6.4).
- **기존 IS 를 IS / PS 로 나눈 것은 사람의 판정이 아니다** (§2.4, D4). Claude 가 사진을 보고 레이어 단위로 정했고, L21 · 17-4 · GP 는 사용자의 규칙 (경사면이 함께 보이면 PS) 을 따랐다.
  MS 의 PS (17 레이어) 는 모양이 뚜렷하다. L21 의 9 레이어는 경사 띠가 보이는지에 따라 IS 5 · PS 4 로 갈렸고 대부분 확신이 중간이다. 틀렸다면 IS 와 PS 를 바꿔 가르친 것이 된다.
  PS 는 74% 가 MS 한 소스이고 자리가 레이어마다 같아 (복사 기준선 0.81), P0 의 PS 점수는 "MS 의 그 자리" 를 외운 것일 수 있다. DIVA 의 PS 로 옮겨 가는지는 따로 봐야 한다.
  IS 는 9 레이어뿐이고 검증은 두 장이다. P0 의 IS 점수는 그만큼 흔들린다.
  17-4 · GP 의 7 레이어는 원본의 경계선에서 영역을 채운 것이다 (1.36 M px). 선의 어느 쪽인지는 분명하지만 채운 화소는 원본 주석이 Powder 로 둔 곳이다.
- **Peregrine 주석과 DIVA 레이블의 정의 차이.** IS (D4 · D5), Soot (D10), Debris (기존 정의가 더 넓음), Swelling (D3). A1 과 M0 의 차이가 이 비용을 보여 준다.
  선으로 칠하는 RH · RS 는 칠하는 굵기도 정의의 일부다 (Peregrine MS 의 RH 는 1036² 에서 3.3 px 굵기의 선 수백 개다, §1.1-13). 첫 내보내기에서 DIVA 의 굵기를 확인한다.
- **얇은 결함과 해상도.** 원본이 큰 공정은 1036² 로 줄일 때 RS · SP 가 사라질 수 있다 (§5.7). 타일 단위 추론은 서빙 경로를 바꿔야 해서 이번 범위 밖이고,
  축소 배율이 큰 공정에서 RS · SP IoU 가 눈에 띄게 낮으면 다음 버전의 첫 후보다.
  v5 에서 L21 의 RS (1036² 에서 굵기 1.8 px) 는 L21 을 통째로 뺐을 때 IoU 0.056, L21 레이어가 학습에 들어갔을 때도 0.104 였다. 굵기가 3 px 이상인 소스 (GP · MS · I2) 는 0.39–0.52 다 (§1.1-14).
  장비 차이가 아니라 해상도의 문제이고, 1036² 에서 2 px 보다 가는 선은 이 입력 크기로는 잡히지 않는다고 본다. DIVA 의 RS 가 그 굵기라면 학습을 더 해서 풀리지 않는다.
- **MS 의 RH 주석은 보이는 선의 일부만 칠했다** (§1.1-13). 칠하지 않은 선은 Powder 로 학습되고, 모델이 그 선을 RH 로 내면 틀린 것으로 세어진다. RH 의 정밀도와 IoU 는 그만큼 낮게 나온다.
  P0 는 v5 와 조건을 맞추려고 주석을 그대로 쓴다. P0 의 RH 예측 그림을 본 뒤에 선 주변의 Powder 를 미레이블 (−1) 로 두는 변형을 검토한다 — 아직 정한 것이 아니다.
- **`recoat_axis` · `swap_sd` 는 사람이 넣는 값이다.** 틀리면 RS / RH 나 두 이미지가 조용히 뒤바뀐다. `build_cache` 의 점검 (§3.2) 과 D6 로 줄인다.
- **GPU 를 서빙과 나눠 쓴다.** 2026-11-16 기준 `defsegam-api-v4` 와 `diva-sam-service` 가 GPU 0 · 1 에 3–4 GB 씩 올라가 있다.
  학습 (GPU 당 23.6 GB — v5 에서 측정) 중에 DIVA 의 `/predict/batch` 가 겹치면 OOM 이 날 수 있다.
  v5 의 풀런 중에 GPU 0 · 1 은 32.6 GB 가운데 27.3 · 26.2 GB 까지 찼다 (2026-11-17).

**범위 밖**: `DefSegAM_API` 구현, DIVA 쪽 수정, 타일 추론, backbone 변경, 논문 원고 (11-class 결과는 v4 기준 그대로).
