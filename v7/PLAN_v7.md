> v6 ([PLAN_v6.md](../v6/PLAN_v6.md), [RESULTS_v6.md](../v6/RESULTS_v6.md)) 의 후속. 작성일 2026-11-18.
> **상태 (2026-11-19): 기준선 다섯 번 (T2), 합성 세트 `w600_v1` (T3 · T4), 합성을 넣은 학습 두 번 (T5) 까지 끝났다 — 바로 아래 "구현 상태".**
> **결과: 대상 클래스의 평균 (T) 은 두 fold 모두 기준선과 같다. `inlayer` 에서는 RS 가 올랐고 (0.260 → 0.306) DB 가 내렸으며, `loso_L21` 에서는 SP 를 잃었다 (0.196 → 0.064 — 부작용).**
> 2026-11-19 에 판정 fold 를 `inlayer` 하나에서 `inlayer` · `loso_L21` 둘로 되돌렸다 (§7 의 V12 — 이미 돌아간 `loso_L21` 기준선 세 번을 쓴다).
> v7 = **v6 의 모델 · 클래스 (10개) · 학습 방식 · 채점을 그대로 두고, 학습 데이터에 "합성 레이어" 를 한 도메인으로 더한 것**이다.
> 합성 레이어는 GenAug 의 생성 모델 ([PLAN_GENAUG.md](../genaug/PLAN_GENAUG.md), `checkpoints/genaug/fill_w256/`) 이 라벨 맵을 보고 그린 사진 두 장이다.
> 원칙은 v5 · v6 와 같다 — DSCNN 예측은 학습 · 길이 · 선정 어디에도 쓰지 않는다. 합성 데이터는 학습에만 쓰고, **판정은 떼어 둔 진짜 사람 GT 로만** 한다.
> "제안값" · "추정" 이라고 적은 수치는 재지 않은 값이다. 그 밖의 수치는 v6 결과 문서와 2026-11-18 의 점검에서 잰 것이고 출처는 부록 A 에 있다.
> 이 문서는 PLAN_GENAUG 의 §3.8 (섞는 법) · §5 (분할 모델 실험) · §6 의 S3–S6 을 대신한다. 달라진 곳은 부록 B 에 모았다.

**한눈에**

1. **v7 폴더로 하되, v6 의 코드는 복사하지 않고 그대로 불러 쓴다 (§0).** `v7/` 에는 더하는 것만 둔다 — 합성 세트를 읽는 쪽과 학습 스크립트 하나다.
   v6 의 코드와 결과는 건드리지 않는다. `genaug/` 는 합성 데이터를 만들고 `v7/` 은 그것을 읽어 분할 모델을 학습시킨다.
2. **더하는 것은 하나다 — 라벨 맵으로 그린 합성 레이어 (§2).** ORNL 빌드의 CAD 파트 배치 위에 결함을 규칙대로 얹은 라벨 맵을 만들고, 생성 모델이 그 라벨 맵대로 1036² 사진 두 장을 그린다.
   진짜 화소는 사진 가장자리 5% 뿐이고 (그 장비의 밝기를 맞추는 기준이다), 안쪽의 모든 화소에 정확한 라벨이 있다.
3. **분할 모델의 클래스는 10개 그대로다. 합성 레이어에 넣는 결함은 RS · DB · SE · RH 넷이다 (§1.3).** 결함 여덟 가지를 모두 그려 보고, v6 모델이 그 클래스로 읽는 것만 남겼다.
   IS · PS · SP · OM 은 지금의 생성 모델이 쓸 만하게 그리지 못한다 — 넣으면 틀린 예시가 된다.
4. **기대가 걸린 곳은 둘이다 (§1).** 줄을 토막으로 내는 RS (v6 의 원본 해상도 IoU 0.26, ORNL 사진에서 행 폭의 0.14 만 이음) 와, 본 적 없는 장비 (기준선은 `loso_L21` 에서 결함 화소의 73% 를 놓친다).
   v6 에서 가장 낮은 IS (재현율 0.24) 와 OM 은 이 계획으로 오르지 않는다. 사람 레이블이 답이다.
5. **클래스 불균형 가운데 이 계획이 건드리는 것은 "예시의 가짓수" 다 (§1.5).** 화소 수의 불균형은 v6 가 이미 가중치 · 추출 · Copy-Paste 로 다루고 있고, 남은 문제는 드문 결함이 든 레이어가 몇 장뿐이라는 것이다.
   합성 세트는 네 클래스에서 그것을 늘린다. 가장 심한 IS · OM 은 늘리지 못한다.
6. **판정은 진짜 사람 GT 두 fold 로, 미리 정한 문턱으로 한다 (§4).** `inlayer` (아는 소스에서 해가 없는가, RS 가 오르는가) 와
   `loso_L21` (그 장비의 주석 없는 사진만 있을 때 놓침이 줄어드는가). 기준선은 두 fold 모두 seed 셋으로 돌려 seed 에 따른 흔들림을 쟀다 (2026-11-19) — v5 · v6 는 잰 적이 없던 값이다.
7. **드는 것**: 합성 세트 600 장에 GPU 2대로 70분 (만들었다). 분할 모델 학습은 첫 판정까지 2회 × 2시간 (합성을 넣은 두 fold, GPU 4대 — 기준선 5회는 끝났다). 효과가 보이면 6회쯤 더 돈다.
8. **효과가 없을 수 있다 (§8).** 합성 결함은 사람 GT 87 레이어의 생김새를 다시 그린 것이고, v6 모델은 그렇게 그린 DB · SE · RH 의 89–97% 를 이미 알아본다.
   그 경우에도 남는 것은 "생성한 레이어로는 오르지 않는다" 는 측정과, 뒤의 모든 비교에 쓸 seed 셋짜리 기준선이다.

## 0. 왜 v7 인가, 코드는 어떻게 두는가

**v7 로 하는 까닭.** PLAN_GENAUG 의 처음 안은 v6 의 학습 코드에 옵션으로 넣는 것이었다. 그러면 v6 의 결과 (RESULTS_v6) 를 낸 코드가 바뀌고, 산출물이 v6 의 폴더에 섞인다.
v7 로 두면 v6 는 손대지 않은 기준선으로 남고, 실행은 `…_10cls_v7-<꼬리표>-s<seed>` 로 따로 쌓인다.

**코드는 v6 를 복사하지 않고 불러 쓴다** (2026-11-18 결정). v7 은 "v6 + 합성 도메인 하나" 라서 나머지가 v6 와 글자 그대로 같아야 하고, 불러 쓰면 그것이 저절로 지켜진다.

| | 통째로 복사한다 (이 문서의 첫 판) | **불러 쓴다 (결정)** |
|---|---|---|
| v6 와 같아야 하는 부분 | 사본이 따로 놀 수 있다 (한쪽만 고친 버그) | 같은 코드다 |
| 새로 쓰는 양 | 약 5천 줄의 사본과 수정 | 새 파일 몇 개 (§5.2). 학습 스크립트 하나만 v6 의 것을 복사해 고친다 |
| v6 가 바뀌면 (DIVA 내보내기 — P1 등) | v7 에 옮겨야 한다 | 따라온다. 그 대신 v6 를 고칠 때 v7 이 깨지지 않는지 함께 봐야 한다 |
| 저장소의 규칙 ("버전끼리 임포트하지 않는다") | 지킨다 | **예외다.** 클래스와 학습 방식이 v6 와 같은 덧붙임이라서 두는 예외이고, CLAUDE.md 에 적는다 |

- **학습 스크립트만은 사본이 필요하다.** v6 의 `training/train.py` 는 처음부터 끝까지 한 함수 (`main`) 라서 밖에서 끼워 넣을 자리가 없다.
  합성 도메인이 손대는 곳이 그 함수 안의 여섯 군데다 — 표본 읽기, fold 나누기, 통계 (class weight · 채점 클래스 목록), Copy-Paste 의 조각 목록, 추출 가중, 기록.
  v6 를 고치지 않으려면 이 파일 하나는 v7 의 것을 따로 둔다. 데이터 읽기 · 증강 · Copy-Paste · 손실 · 채점 · 요약은 v6 의 것을 그대로 부른다.
- 채점과 요약은 v6 의 스크립트에 run 이름만 바꿔 준다 (`--run-name`). 그래서 v7 실행의 그림 폴더도 `figures/<run>/v6/…` 로 쌓인다 (v6 코드가 그 이름을 쓴다).
- **역할을 나눈다.** `genaug/` = 합성 데이터를 만든다 (생성 모델, 레이어 그리기, 세트 저장, 점검). `v7/` = 그것을 읽어 분할 모델을 학습시킨다.
  v7 은 `genaug` 를 임포트하지 않고 세트 폴더만 읽는다. 그래서 규칙으로 만든 세트 ([PLAN_RULESYNTH.md](../rulesynth/PLAN_RULESYNTH.md)) 도 같은 구성이면 v7 에 그대로 넣을 수 있다.
- **v7 은 실험의 이름이지 "v6 보다 나은 모델" 이라는 뜻이 아니다.** §4.3 의 판정을 넘지 못하면 서빙 후보는 v6 그대로이고, v7 은 "합성 레이어는 듣지 않았다" 는 기록으로 남는다.

### 1.3 v6 모델은 합성 레이어를 어떻게 읽는가 — 결함 여덟 가지를 모두 그려 봤다

합성 레이어를 v6 의 P0 모델 (`cv/inlayer/last.pt`) 에 넣고, 그리라고 한 라벨과 예측을 안쪽 화소에서 견줬다.
두 번에 나눠 쟀다 (한 번에 6장 — B3 · B4 · B5 의 CAD 배치 2장씩, 가장자리 기준 있음). 모양은 RS 만 직선이고 나머지는 사람 GT 의 진짜 모양이다.

- 인식률은 **0 이 아닌지**를 보는 값이지 높을수록 좋은 점수가 아니다. 모델이 이미 다 알아보는 사진은 가르칠 것이 적다 (PLAN_GENAUG §4).
- 넣지 않는 넷은 "v6 가 못 알아봐서" 가 아니다. 그림을 봐도 그 클래스로 보이지 않는다 (PS 는 옅은 테두리만, 넓은 SP 는 마스크 모양의 얼룩, IS 는 제각각). 그대로 넣으면 그 라벨을 단 다른 것을 가르치게 된다.
- **라벨을 더 세게 따르게 그리면 (guidance 2 → 4, 같은 레이어 · 같은 라벨 맵) 갈린다.** 넣는 넷은 더 잘 읽힌다 (RS 63–68% · RH 97% · SE 94% · DB 99%).
  OM 은 19% → 51% 로 오르고 (화소 875 개의 작은 표본), PS 는 0% → 40% 로 오르지만 그림은 가장자리가 반듯한 거친 얼룩이라 그 클래스처럼 보이지 않는다.
  IS 는 그대로 1% 이고 63% 가 PS 로 읽힌다. SP 는 더 나빠진다 — 작은 것 3% (Debris 83%), 넓은 것 17% (Debris 51%).
  곧 **IS · SP 는 설정으로 풀리지 않고, OM 은 후보가 된다** (§7 의 V11). 수치는 `check_2026-11-18/v7_probe/guidance4/` 에 있다.
- P0 모델은 L21 (ORNL 빌드와 같은 기종) 16 레이어를 학습에서 본 모델이다. 그 장비를 본 적 없는 모델이 이 레이어를 얼마나 읽는지는 `loso_L21` 기준선 모델로 잰다 (§2.6 의 K6).

### 1.4 그래서

- **주 방식은 "라벨 맵 → 레이어" 다.** 흔적 (도포 직후 사진의 결, 창 사이의 얼룩) 이 레이어 전체에 깔려 결함의 자리와 상관이 없다.
  결함 자리만 그려 넣는 방식은 흔적이 결함 자리에만 남는다.
- **대상 클래스는 RS · DB · SE · RH 다.** 넷 모두 그려지고 v6 가 그 클래스로 읽는다.
- **기대의 크기를 미리 적는다.** `inlayer` 에서 DB · SE · RH 는 큰 변화를 기대하지 않는다 (P0 모델이 이미 89–97% 를 읽는다).
  기대는 RS (두 fold 모두) 와 `loso_L21` 의 놓침에 있다.

### 1.5 클래스 불균형과 이 계획

불균형은 두 가지이고, 이 계획이 건드리는 것은 둘째다.

| | 무엇이 치우쳐 있나 | v6 가 이미 하는 것 | 남은 문제 |
|---|---|---|---|
| ① 화소 수 | 라벨된 화소의 74.5% 가 Powder 다. OM 은 0.035% 다 (2천 배 차이) | class weight (Powder 0.58, 드문 결함은 상한 10), 표본 추출의 절반을 클래스 균등으로, Copy-Paste (RH · SE · OM · DB) | 거의 없다. 오히려 결함 쪽으로 기울어 있다 — 재현율은 높고 정밀도가 낮다 (RH 0.89 / 0.37). 외운 레이어에서도 정답보다 넓게 칠한다 (결과 문서 §2.3) |
| ② 예시의 가짓수 | 그 결함이 든 레이어가 몇 장뿐이다 — IS 9, OM 20 (2 소스), RH 25 (1 소스), PS 33, RS 37, DB 43, SP 67, SE 75 (125 레이어 가운데) | 없다. 가중치는 같은 예시를 더 세게 볼 뿐이고, Copy-Paste 는 같은 조각을 다른 자리에 놓을 뿐이다 | **v6 가 낮은 까닭이 이것이다.** IS · RS 는 외운 레이어에서 0.97 · 0.81 이고 처음 보는 레이어에서 0.23 · 0.26 이다 |

|---|---|---:|---|---:|
| RS | 0.29 M · 2,320 | 37 | 301 장 · 0.96 M · 1,594 | 23% |
| DB | 0.27 M · 2,160 | 43 | 311 장 · 0.96 M · 1,605 | 24% |

- **세트의 클래스 구성을 목표로 정하고 만든다.** 네 클래스가 각각 합성 레이어의 절반쯤에 들어가게 하고, **레이어당 평균 화소 수가 사람 GT 의 그것을 넘지 않게** 줄 수 · 개수를 맞췄다 (2026-11-19).
  기준을 "세트 전체의 화소 합" 에서 "레이어당 평균" 으로 바꾼 것이다 — 학습에서 한 클래스를 얼마나 보는가는 [그 도메인을 뽑는 몫] × [레이어당 평균 화소] 로 정해지기 때문이다.
  레이어당 평균이 사람 GT 와 같으면 그 클래스 화소 가운데 합성의 몫이 추출의 몫 (0.3) 과 같아지고, 넘으면 합성 쪽이 그 클래스를 지배한다. 처음 적었던 값 (화소 합 0.1–1 M) 대로면 합성의 몫이 2–13% 에 그친다.
  마지막 열은 고르게 뽑는다고 보고 낸 어림이다 — 사람 GT 쪽은 클래스 균등 추출과 Copy-Paste 로 드문 결함을 더 자주 보므로 실제 합성의 몫은 이보다 작다. `manifest.json` 에 클래스별 화소 수 · 레이어 수가 있다.
- **class weight 는 사람 GT 로만 계산한다 (§3).** 합성을 넣었다고 손실의 가중이 달라지지 않게 한다.
- **합성에 없는 클래스는 보는 횟수가 준다.** 합성의 몫 0.3 만큼 사람 GT 를 덜 뽑으므로 IS · OM · SP · PS 의 예시를 보는 횟수가 30% 준다. 가장 약한 IS · OM 이 여기 들어 있다.
  §4.3 의 부작용 한도로 지켜보고, 내려가면 몫을 줄인다.
- **가장 심한 IS · OM 은 이 계획 밖이다.** 생성 모델이 배울 예시가 8개 · 70개뿐이라 그리지 못한다. 사람 레이블 (DIVA) 과 v6 의 D10 이 답이다.
- **이 계획에 넣지 않은 것 — 손실 쪽의 조정.** ① 이 결함 쪽으로 기울어 있다는 것 (class weight 의 상한 10) 은 합성과 무관한 변수라 여기서 함께 바꾸지 않는다.
  따로 한 번 돌려 볼 값어치는 있다 (상한을 낮춘 기준선 1회, 2시간) — 넣을지는 §7 의 V10 이다.

## 2. 합성 세트 — `genaug/` 가 만든다

### 2.1 한 장을 만드는 순서

1. **배경 레이어를 고른다** — 공용 배경 캐시 (`cache/ornl_canvas_sz1036/`) 의 B3 · B4 · B5. 여기서 쓰는 것은 CAD 파트 마스크와 사진의 가장자리 5% 뿐이다.
2. **라벨 맵을 만든다** — 파트 안 = Printed, 밖 = Powder, 파트 경계 ±3 px = 미레이블. 그 위에 §2.2 의 규칙으로 결함을 얹는다.
3. **생성 모델이 안쪽 932² 를 그린다** — 256 창 25개 (5 × 5, 간격 177 px). 진짜 가장자리에 닿은 바깥 창부터 안쪽으로 그리고, 창마다 진짜 가장자리와 먼저 그린 이웃 창을 보고 이어 그린다.
4. **저장한다** — 사진 두 장, 라벨 (안쪽 = 라벨 맵, 가장자리 = 미레이블 −1), 내력 (`manifest.json`).

### 2.2 라벨 맵의 규칙

아래는 2026-11-19 에 사람 GT 87 레이어 (생성 모델이 본 레이어) 를 재고 정한 값이다 (`genaug/synth/label_map.py` 의 `Rules`). 처음 적었던 출발값과 달라진 곳은 "근거" 에 적었다.

| 클래스 | 모양 | 자리 | 한 장에 (그 결함이 드는 장에서) | 근거 |
|---|---|---|---|---|
| RS | 굵기 2 px 의 가로 줄. 절반은 안쪽 끝에서 끝까지, 절반은 200–420 px | 아무 행. **분말 위의 화소만 RS 로 적는다** — 파트를 지나는 구간은 Printed 그대로 둔다 | 1–5 줄 (평균 3) | 굵기는 L21 주석 (1036² 에서 1.8 px). 사람 GT 에서 RS 둘레 (2–6 px) 의 Printed 는 2.9% 뿐이다 — 사람은 파트 위에 줄을 칠하지 않는다 (출발값은 "파트 위도 RS" 였다). 길이의 비율은 정할 값이다 (V8) |
| DB | 사람 GT 87 레이어의 진짜 모양 (뒤집기, 크기 0.8–1.25배, 긴 변 120 px 이하) | 마스크의 90% 이상이 Powder 위 | 중앙값 10 개, 1–40 개 | 사람 GT 에서 DB 둘레의 93% 가 Powder 다. DB 가 든 레이어의 객체 수는 중앙값 16 (평균 24) 이다 |
| SE | 〃 | **파트 가장자리에 걸친다** — 모양의 절반 이상이 CAD 의 파트 안이고 파트 밖에 닿는다 | 중앙값 10 개, 1–36 개 | 사람 GT 의 SE 는 98% 가 Printed 가 아닌 화소에서 3 px 안에 있다 (둘레의 49% 가 Powder, 35% 가 Printed). 출발값 ("90% 이상이 Printed 위") 은 파트 한가운데에 놓는 것이라 진짜와 달랐다. SE 가 든 레이어의 객체 수는 중앙값 12 |

| (결함 없음) | — | — | 3장 중 1장 | 그 장비의 정상 분말 · 파트만 있는 레이어 |

- 결함이 드는 장에서는 클래스마다 0.75 의 확률로 넣는다 (전체로는 클래스마다 레이어의 절반). 개수는 §1.5 의 목표 (레이어당 평균 화소가 사람 GT 를 넘지 않게) 에 맞춘 것이다.
- SE 는 파트 경계의 "모름" 띠 (±3 px) 위에도 SE 로 적는다 — 가장자리에 놓이는 결함이라 띠를 비우면 결함의 대부분이 라벨 없이 남는다.
- **모양은 진짜에서 가져온다.** 직선인 RS 를 빼면 새로 그린 모양을 쓰지 않는다. 생성 모델은 라벨 맵의 모양을 그대로 따라 그리므로 (§1.2), 있을 법하지 않은 모양을 주면 그대로 틀린 예시가 된다.
- 리코팅 축은 가로다 ([PLAN_v6.md](../v6/PLAN_v6.md) §4). RS 는 가로 줄, RH 는 세로 줄이고 라벨 맵을 90° 돌리지 않는다.

### 2.4 누출을 막는 규칙

- 생성 모델은 두 fold 의 검증 레이어 38장 (`inlayer` 의 22 + L21 의 20, 4장이 겹친다) 을 본 적이 없다 (`genaug/splits/holdout_v1.json`).
  결함의 모양도 나머지 87 레이어에서만 가져온다. 그래서 합성 세트 한 벌을 두 fold 에 그대로 쓴다.
- **다른 fold 에는 쓸 수 없다.** `loso_MS` 같은 fold 의 검증 레이어는 생성 모델이 본 레이어다. 그런 fold 로 넓히려면 생성 모델을 다시 학습해야 한다.
  세트의 `manifest.json` 에 쓸 수 있는 fold (`valid_folds`) 가 적혀 있고, v7 의 학습 스크립트는 거기 없는 fold 에 그 세트를 넣으면 멈춘다.
- 배경은 B3 · B4 · B5 만 쓴다 (생성 모델이 본 빌드). B1 · B2 의 사진은 생성 모델도 분할 모델도 보지 않는다.
- 합성 레이어를 분할 모델의 예측으로 **한 장씩 고르지 않는다.** §2.6 의 인식 시험은 클래스를 통째로 넣을지 뺄지만 정한다.
  P0 모델은 L21 을 본 모델이라, 그 모델이 알아본 표본만 남기면 `loso_L21` 의 점수가 부푼다. 그리고 이미 알아보는 것만 남아 합성이 가르칠 것이 줄어든다.

## 3. v7 의 학습 — v6 에서 바뀌는 것만

**그대로 두는 것**: 모델 (DINOv2 ViT-B/14 reg frozen + DPT decoder, 입력 1036²), 클래스 10개, 10,000 step · warmup 300 → cosine, GPU 4대 × 4장, LR 2.83e-4, EMA 0.999,
CE + sqrt-inv class weight, 증강, Copy-Paste (RH · SE · OM · DB), 250 step 마다 검증, 배포 후보 = `last.pt`, 채점 (원본 해상도가 주 지표, TTA · 후처리 없음).
이것들은 값만 같은 것이 아니라 v6 의 코드를 그대로 부른다 (§0).

| 항목 | v6 | v7 | 까닭 |
|---|---|---|---|
| 학습 데이터 | 사람 GT | 사람 GT + 합성 세트 (도메인 `synth`) | 이 실험이 보려는 것 |
| 표본 추출 | 사람 GT 안에서 [그룹 균등 0.5 + 클래스 균등 0.5] | **합성의 몫 0.3** (제안값). 사람 GT 안의 식은 그대로, 합성 안에서는 고르게 뽑는다 | 총 step 이 그대로라 사람 GT 를 뽑는 횟수가 30% 준다. PLAN_GENAUG · RuleSynth 와 같은 값이다 |
| class weight · 채점 클래스 목록 · 배선 검사 | 학습 분할 전체의 화소로 계산 | **사람 GT 표본으로만** 계산 | 합성을 넣어도 손실의 가중과 채점하는 클래스가 달라지지 않게 (§1.5) |
| Copy-Paste | 모든 학습 표본 | 사람 GT 표본에만. 합성 레이어는 조각을 받지도 대지도 않는다 | 합성 레이어에 진짜 조각을 붙이면 흔적이 결함 자리에 생긴다 |
| 증강 | 이동 · 뒤집기 · 180° 회전 · 잡음 · 밝기 | 합성 표본에도 같은 것 | — |
| 손실 | CE, 미레이블 −1 제외 | 그대로. 합성 레이어의 가장자리 (진짜 화소) 는 −1 이다 | 집합 라벨 (−2) 은 쓰지 않는다 — 안쪽 전부에 정확한 라벨이 있다 |
| 검증 · 채점 | 떼어 둔 사람 GT | 그대로 (합성은 채점하지 않는다) | 판정은 진짜 사진으로만 |
| 기록 | 전체 loss | 도메인별 loss · 도메인별 추출 수. `run.json` 에 세트 이름 · 몫 · 합성 표본의 목록을 따로 적는다 | 합성이 손실에서 차지하는 몫을 본다 |
| run 이름 | `…_10cls_v6` | `…_10cls_v7-<꼬리표>-s<seed>` (예: `…_v7-W-s42`) | 실행마다 폴더를 따로 둔다 |

- **합성 세트를 주지 않으면 v6 와 같은 실행이어야 한다.** 같은 seed 에서 같은 표본을 뽑고 같은 loss 를 낸다 (§5.3 의 스모크 1). 그래야 기준선을 v7 의 스크립트로 돌려도 v6 와 이어진다.
- 합성 세트는 학습을 시작할 때 사람 GT 와 함께 RAM 에 올린다 (600 장에 프로세스당 약 1.9 GB — 표본당 3.2 MB 로 계산).

  "주석은 없지만 그 기종의 사진은 있는" 조건이다. DIVA 의 M160 · M280 이 놓인 조건과 같다. 결과를 그렇게 적는다.

- 함께 읽는 것: 클래스별 재현율 · 정밀도, 놓친 비율, 잘못 짚은 비율, 소스별 표 (v6 의 `metrics.json` 그대로).
- **RS · RH 는 재현율과 정밀도를 따로 읽는다.** 사람 주석은 줄의 일부만 칠한다 (L21 의 RS 주석은 줄이 있는 행에서 행 폭의 0.24). 줄 전체를 내도록 배운 모델은 재현율이 오르면서 정밀도가 내려갈 수 있다 (§4.3).

### 4.3 판정 — 결과를 보기 전에 정해 둔다

재는 값 T 는 대상 클래스의 IoU 평균이다. 기준선은 그 fold 의 N 세 실행의 평균이고 σ 는 그 표준편차다. 문턱 0.03 · 0.01 · 1.0%p 는 제안값이다 (PLAN_GENAUG §5.3 과 같은 값).

- **효과**: T 가 기준선 + max(0.03, 2σ) 이상이다.
- **부작용** (하나라도): Powder 또는 Printed 의 IoU 가 기준선보다 0.01 넘게 낮다. 잘못 짚은 비율이 기준선 + 1.0%p 를 넘는다.
  합성에 넣지 않은 클래스 (IS · PS · SP) 가운데 하나의 IoU 가 그 클래스의 max(0.03, 2σ) 넘게 내려간다. (OM 은 검증 화소가 3.3 K 라 참고로만 본다.)

| 결과 (IN-W · LO-W) | 뜻 | 다음 |
|---|---|---|
| 한 fold 이상에서 효과, 어느 fold 에도 부작용이 없다 | 합성 레이어가 듣는다 | 2단계 — seed 43, 무엇이 들었는지 (W-RS · W-noRS · N+CP-RS) → 3단계 |
| 두 fold 모두 문턱 안이고 부작용이 없다 | 이 형태로는 차이가 없다 | 클래스별 재현율을 읽는다. RS 의 재현율만 0.10 넘게 올랐으면 W-RS 를 한 번 돌린다. 아니면 멈추고 K4 · K5 · K6 의 값과 함께 적는다 |
| 어느 fold 에서든 부작용 | 합성이 해친다 | 몫 0.15 로 한 번. 그래도 해치면 P 를 한 번. 그래도면 멈춘다 |

- **RS 를 읽는 법.** 재현율이 오르고 정밀도가 그대로면 효과다. 재현율이 오르고 정밀도가 내려가면, 늘어난 RS 예측이 사진에서 줄이 보이는 자리인지를 먼저 잰다
  (v6 결과 문서 §3.4-2 의 방법 — 그 행이 위아래 행보다 어두운 정도). 그리고 그 그림을 사용자가 본다. 줄이 보이는 자리라면 주석이 덜 칠해진 것이고, 아니면 잘못 짚은 것이다.
- **N+CP-RS 를 읽는 법.** RS 를 Copy-Paste 에 넣는 것만으로 W 와 같은 만큼 오르면 RS 에는 생성 모델이 필요 없다. 그때는 더 싼 쪽을 쓴다.
- 읽을 때는 평균 하나가 아니라 클래스별 재현율과 놓친 비율을 먼저 본다. 이 계획이 겨냥한 것이 놓침이다.

### 4.4 참고로만 보는 것 — ORNL 100 레이어

FULL-W 를 v6 의 `ornl_compare` 와 같은 100 레이어에서 v6 `full` 과 나란히 놓는다. 사람 GT 가 없는 사진이라 점수가 아니고, 판정에 쓰지 않는다 ([PLAN_v6.md](../v6/PLAN_v6.md) §6.5).

- 볼 것: RS 가 가로로 이어지는 정도 (v6 는 행 폭의 0.14), RS 로 낸 행의 수, SP · Debris 의 넓이, 고정 위치의 Debris.
- B3 · B4 · B5 의 60 레이어는 합성 세트의 배경 빌드다 (CAD 와 가장자리를 썼다). B1 · B2 의 40 레이어가 어느 모델도 보지 않은 사진이다 — 둘을 갈라 적는다.

## 8. 위험 요소

- **효과가 없을 수 있다.** 합성 결함은 87 레이어의 생김새를 다시 그린 것이다. v6 P0 모델이 그린 DB · SE · RH 의 89–97% 를 이미 읽으므로 `inlayer` 에서는 가르칠 것이 적다.
  기대는 RS 와 `loso_L21` 에 걸려 있고, 그쪽도 "놓침의 원인이 낯선 배경" 일 때만 듣는다. 원인이 결함의 생김새라면 듣지 않는다 (PLAN_GENAUG §0).
- **합성의 티.** 생성한 분말은 두 사진 모두 진짜보다 매끈하다 (결이 진짜의 0.60 — §1.2). 분할 모델이 합성과 진짜를 가려 보면 합성에서 배운 것이 진짜 사진으로 옮겨 가지 않는다.
  결함의 자리와 상관없는 흔적이라 "흔적 = 결함" 을 배우지는 않지만 효과를 묽게 한다. K5 가 미리 재고, 판정은 진짜 사진으로만 한다.
  학습의 잡음 증강이 이 차이를 가려 주지는 않는다 — 재 보니 그 증강은 0.5 단계짜리 변화만 준다 ([PLAN_AUG.md](PLAN_AUG.md) §1. 2026-11-19 에 "밝기의 1% · 10% 의 잡음을 얹는다" 고 적었던 것은 틀렸다).
  창 사이의 얼룩은 재 보니 진짜 사진 수준이었다 (K4).
- **생성한 정상이 진짜보다 깨끗하다.** v6 는 진짜 ORNL 분말의 4.2–5.1% 를 SP 로 내는데 생성한 분말에서는 1.5–1.9% 다. 그 차이만큼 합성 레이어의 Powder 라벨이
  "이 장비의 분말에는 그을음이 없다" 고 가르칠 수 있다. L21 의 SP (`loso_L21` 기준선 0.20, `inlayer` 의 L21 줄 0.58) 가 내려가는지를 §4.3 의 부작용 한도로 본다.
- **합성에 없는 클래스를 덜 본다.** 몫 0.3 만큼 사람 GT 를 덜 뽑는다. 가장 약한 IS · OM 이 그쪽이다 (§1.5).
- **RS 의 정답 기준이 사람 주석과 다르다.** 합성에서는 그린 줄 전체가 RS 고, 사람은 줄의 일부만 칠했다. IoU 하나로 읽으면 좋아진 것이 나빠진 것으로 보일 수 있다 (§4.3 의 "RS 를 읽는 법").
- **틀린 예시.** 생성 모델은 라벨 맵을 그대로 따라 그리므로 규칙이 틀리면 그대로 틀린 정답이 된다. SE 를 파트 한가운데 놓는 것, RH 를 M2 의 사진에 넣는 것 (RH 주석은 MS 한 소스에만 있다) 이 그런 후보다.
  SE 는 사람 GT 를 재서 파트 가장자리에 놓도록 고쳤다 (§2.2). RH 는 K1 에서 사용자가 보고, L21 에서 RH 를 잘못 짚는 화소가 늘지 않는지 본다 (`loso_L21` 의 잘못 짚은 비율).
- **v6 를 불러 쓴다.** v6 의 코드가 바뀌면 v7 의 동작도 바뀐다. v6 를 고친 뒤에는 §5.3 의 스모크 1 을 다시 돌리고, 실행 사이에 v6 가 바뀌었으면 그 실행들을 한 표에 놓지 않는다.
- **누출.** 생성 모델이 본 레이어, 합성 레이어를 고르는 방법 (§2.4). 두 fold 밖으로 넓히면 생성 모델부터 다시 학습해야 한다.
- **한 장비뿐이다.** 주석 없는 사진은 ConceptLaser M2 것만 있다. 이 계획이 보일 수 있는 것은 그 장비에서의 효과다.
- **기준선이 움직일 수 있다.** D10 · D4 로 데이터셋을 다시 변환하면 기준선 다섯 번 (과 v6 의 P0) 을 다시 돌려야 한다 (V7).
- **비용.** 첫 판정까지 GPU 4대로 4시간이 남았고 (기준선 10시간은 끝났다), 그동안 다른 학습과 합성 세트 만들기를 함께 돌릴 수 없다.

## 9. 범위 밖 · 그 다음

**이 계획에서 하지 않는 것**: IS · OM · SP · PS 를 올리는 일 (사람 레이블과 주석 기준의 몫이다), 카메라에 붙은 점을 Debris 로 내는 것 (v6 결과 문서의 권장대로 서빙 쪽 후처리),
DIVA 내보내기 (v6 의 P1), 서빙 인계, 생성 모델의 재학습 (V9 로 미뤘다), 손실 쪽의 조정 (V10), 논문 원고.

**효과가 확인되면**

1. 세트를 2,000 장으로 늘리고 전수 학습 모델 (FULL-W) 을 만든다.
2. 생성 모델을 다시 학습한다 (V4 · V9) — 빌드 · 소스 입력을 넣으면 가장자리 기준 없이 그리고, 사람 GT 소스의 화풍으로도 레이어를 만들 수 있다.
3. **DIVA 장비로 옮긴다.** M160 · M280 의 주석 없는 사진과 파트 마스크가 오면 같은 절차를 돌린다. 사람 레이블이 모이기 전에 그 장비의 배경에 결함을 놓은 학습 자료가 생긴다.
   PLAN_GENAUG 가 적은 이 일의 목적지다.
4. 규칙 기반 합성 ([PLAN_RULESYNTH.md](../rulesynth/PLAN_RULESYNTH.md)) 의 세트를 v6 클래스로 다시 써서 같은 표에서 견준다. 세트의 구성이 같아 v7 이 그대로 읽는다 (집합 라벨 −2 는 −1 로 읽는다).
